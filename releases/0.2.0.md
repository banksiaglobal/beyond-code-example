# 0.2.0 — payment retry identity

## Fixed

- Retrying the same payment attempt after an ambiguous provider timeout no longer creates another simulated provider charge.

## Changed

- Payment attempts now have stable identity through `AttemptKey`.
- A local attempt is persisted before provider invocation.
- Different attempt keys represent different payment attempts while the order remains unpaid.

## Known limitations

- The ObjectScript source and regression tests were reviewed but not compiled or executed for this release.
- Real payment providers are not represented.
- Concurrent processing, provider reconciliation, and webhook deduplication remain outside this example.

See the [deployment and verification guidance](../deployment/DEPLOY.md) for the intended 0.2.0 checks.
